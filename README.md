# Решись Авиа — Ганин Андрей Павлович

Вариант C: веб-страница и backend API FastAPI. Реализованы расчёт, график девяти квантилей, регистрация, вход, выход и серверная проверка сессии перед расчётом. Приложение опубликовано на Render: https://reshis-avia-ganin.onrender.com . Исходный код: https://github.com/AndreiGanin2910/reshis-avia-ganin .

## Запуск

Рекомендуется Python 3.11 или 3.12. Откройте терминал в папке с `app.py`.

macOS/Linux:
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Windows PowerShell:
```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000 . Не открывайте index.html двойным щелчком: ему нужен работающий API. Документация API: http://127.0.0.1:8000/docs . Остановка сервера: Ctrl+C.

## Регистрация и вход

Нажмите «Регистрация», укажите имя, уникальный логин и пароль от 10 до 128 символов, подтвердите пароль. После регистрации вход выполняется автоматически. В шапке появляется имя, расчёт становится доступен. Вход сохраняется после обновления страницы. Кнопка «Выйти» отзывает серверную сессию, включая доступ через API. Для повторного входа используйте «Войти»; регистр логина не учитывается.

Готового общего аккаунта нет. Тестовые аккаунты и базы не входят в архив. Электронная почта не требуется. Отправка писем и восстановление пароля не реализованы.

Пароли хранятся как Argon2id-хеши с индивидуальной солью. Для сессии создаётся случайный токен, в базе хранится только его SHA-256. Cookie имеет HttpOnly и SameSite=Lax, при HTTPS или COOKIE_SECURE=1 включён Secure. Сессия действует 7 дней и отзывается при выходе. POST расчёта и выхода дополнительно требуют X-CSRF-Token. Ограничение частоты попыток работает в пределах одного процесса.

Локально пользователи и сессии сохраняются в var/accounts.sqlite3. Файл переживает обычный перезапуск, его нельзя добавлять в открытый репозиторий или архив сдачи. На хостинге используется DATABASE_URL PostgreSQL. На Render программа отказывается запускаться без DATABASE_URL, чтобы аккаунты не оказались на непостоянном диске. Публичное приложение должно работать по HTTPS.

## Данные и собственный прогноз

Подключён собственный прогноз `data/my_forecast.csv`, полученный моделью AutoETS из выполненного ноутбука. В файле 155 рейсов, даты 1 июня — 1 июля 2026 года, отрицательных квантилей спроса при базовой цене нет.

`data/seasonal_forecast.csv` оставлен как резервный пример авторов. Он используется только при отсутствии файла. Переменная FORECAST_PATH позволяет явно выбрать другой CSV. После замены данных перезапустите сервер.

## Расчёт

Для квантиля X:
```
спрос_X = X_base_demand - price_sensitivity * (price - base_price)
продажи_X = min(seats, max(0, спрос_X))
```

Карточки показывают квантиль 0.5. График показывает спрос без отсечения по местам, чтобы была видна нехватка вместимости. Медиана графика точно совпадает с карточкой спроса. Отрицательное значение линейной формулы означает нулевые продажи; интерфейс это объясняет. Дробный прогноз не округляется до расчёта продаж, только отображается с одним десятичным знаком.

«Сравнить цены» показывает медианные продажи и загрузку, а также маржу при слабом (q0,1) и медианном (q0,5) спросе. Можно сопоставить базовый и введённый тарифы с ценами `0.1_price` и `0.5_price` из CSV. График показывает обе кривые маржи в допустимом диапазоне тарифов, отмечает сценарные цены и базовый тариф. Каждая кнопка подставляет свою сценарную цену в форму и пересчитывает прогноз. Маржа равна продажам, умноженным на разницу цены и затрат на одного пассажира. Постоянные расходы рейса в расчёт не входят.

seats — общая вместимость, а не фактическое число свободных мест. В данных нет текущих бронирований; «остаток по прогнозу» равен seats − прогноз продаж. Квантили не считаются девятью равновероятными исходами.

`*_price_demand` исходного ноутбука содержит спрос без ограничения местами. Приложение не использует этот столбец как готовый прогноз продаж: заново считает спрос при введённой цене.

Диапазон цены берётся из routes.csv. Неизвестные маршрут или дата, отрицательная или выходящая за диапазон цена отклоняются. При старте проверяются обязательные столбцы, числа, дубликаты, вместимость и порядок квантилей.

## Проверка

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Все 18 тестов из публичного репозитория прошли. Проверены формулы и все 155 рейсов, регистрация, Argon2id, cookie, верный и неверный пароль, занятый логин, ограничение запросов, серверная проверка доступа, CSRF, смена токена при входе, отзыв и истечение сессии, сохранение аккаунтов после повторного открытия базы. В предыдущей версии в браузере проверены регистрация, расчёт, сохранение входа после обновления страницы, выход и повторный вход. После обновления прогноза повторно выполнены автоматические проверки.

Код содержит поддержку PostgreSQL через SQLAlchemy и psycopg. На публичном Render-сервисе с PostgreSQL проверены регистрация, сохранение входа после обновления страницы, контрольный расчёт, выход, отказ при неверном пароле и повторный вход. Перезапуск production-сервиса отдельно не проверялся.

Контрольные примеры для собственного прогноза: MOW-AER, 12.06.2026, вместимость 900 мест.

| Цена | Медианный линейный спрос | Продажи | Остаток по прогнозу |
| ---: | ---: | ---: | ---: |
| 9000 ₽ | 852 | 852 | 48 |
| 10000 ₽ | 711 | 711 | 189 |
| 18000 ₽ | −417 | 0 | 900 |

В API отрицательный линейный спрос при высокой цене сохраняется для графика, а продажи ограничиваются нулём. Это не отрицательный базовый квантиль: на входе базовые квантили уже обработаны. Пример 970/829 из задания относится к резервной демонстрационной таблице и не описывает собственный прогноз.

CSV хранит спрос при базовом тарифе, округлённый до пассажира. Цены рассчитаны по формуле из ноутбука организаторов на исходном прогнозе спроса и округлены до рубля при выгрузке. Для контрольного рейса цена при слабом спросе 8859 ₽, при медианном 9622 ₽.

## Реализованные функции и сдача

- Вариант C — да: HTML/CSS/JavaScript + FastAPI.
- Простое прогнозирование — да.
- График распределения в виде квантильной кривой — да.
- Регистрация — реализована.
- Авторизация, выход и проверка доступа на сервере — реализованы.
- Публикация на хостинге — выполнена: https://reshis-avia-ganin.onrender.com . Инструкция — DEPLOY.md.

API аккаунта: POST /api/auth/register, POST /api/auth/login, GET /api/auth/me, POST /api/auth/logout. Расчёт POST /api/predict требует сессию и X-CSRF-Token. Интерфейс получает и передаёт токен автоматически. GET /healthz проверяет приложение и подключение базы.

Статический хостинг сам по себе не запускает FastAPI: для публикации нужен сервис с поддержкой Python web application. HTML и API обслуживаются одним сервером; отдельный CORS в этой конфигурации не нужен.
